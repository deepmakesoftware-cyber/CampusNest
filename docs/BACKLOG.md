# CampusNest — Feature Backlog

Features we have agreed to add **later**, outside the current phase plan (see [PROJECT-PLAN.md](PROJECT-PLAN.md)).
Planned phase work (listings, scoring, roommates, etc.) is not listed here.

**How to use this list:** add new ideas at the bottom with status **Pending**. When we start one, change it to
**In progress**, and when it is done and tested, mark it **Done** and record it in [STATUS.md](STATUS.md).

| ID | Feature | Status | Why later | Notes / prerequisites |
|---|---|---|---|---|
| B1 | **Sign up / log in with Google** | Pending | Not a faculty requirement; needs internet during demos; the review is in about a week | Free (no credit card for basic sign-in). A team member creates a Google Cloud project + OAuth client ID/secret and puts them in `.env`. Needs: role choice (student / provider) after first Google login, linking to an existing account with the same email, nullable password for Google-only accounts (new migration). Testing mode allows 100 manually added test users and shows an "unverified app" warning. Estimate: ~1 day incl. tests. Suggested timing: after the review, with Phase 8 trust work (Google confirms the email address). |
| B2 | Change password (while logged in) | Pending | Not needed for the demo | Requires current password; end other sessions after change. |
| B3 | Forgot password / reset by email | Pending | Needs a free email-sending service | Must stay free; time-limited single-use reset tokens. Related to tech debt T11. |
| B4 | Email address verification | Pending | Needs a free email-sending service | Would also address T10 (registration revealing existing emails). Comes free for Google sign-in users (B1). |
| B5 | **Simple step-by-step listing wizard** for owners who are not comfortable with long forms | Pending | Current form works and is tested; review is in a week. Raised by Deep after trying the owner flow (2026-11-01) | One question per screen with a progress bar ("Step 2 of 6"): **1** What kind of place? (big picture buttons) → **2** Where is it? → **3** Rooms (+/− counters instead of typing; people-per-room filled in automatically from room type) → **4** Rent and extra charges → **5** What do you provide? (tap icon tiles, Yes/No) → **6** Photos (open phone camera directly) → review and submit. Plain words, large touch targets, optional fields hidden under "More details", automatic draft saving. Mostly frontend: the existing API and checklist stay the same. Validate with 2–3 real PG owners (also good material for the viva). |
| B6 | Hindi and Marathi interface | Pending | Needs translation of every screen and a language switcher | Start with the owner wizard (B5) and listing pages. Use a free i18n approach; translations reviewed by a native speaker, not machine-only. |
| B7 | Assisted listing: CampusNest staff create a listing on an owner's behalf (e.g. over a phone call) | Pending | Needs a new admin flow and owner consent step | Admin creates a draft linked to the owner's account; the owner confirms it before it can be published, so they stay responsible for the content. Helps owners who can't use the app themselves. |
| B8 | Easier location entry: "Use my current location" button and address search | Pending | Small, but not needed for the demo | Browser geolocation is free and needs no API key (works when the owner is standing at the property). Hide latitude/longitude fields under "Enter coordinates manually". Address search via Nominatim must respect its 1 request/second policy. |
| B9 | **Local-train-aware commute planner + true monthly cost** (distinctive-functionality proposal to faculty, 2026-11-23) | Pending (proposed, awaiting faculty review) | Must be reviewed by faculty before implementation | Replaces the straight-line train estimate (T22) with a graph of the Mumbai suburban lines (stations in line order + interchange transfer edges) and a multi-source Dijkstra search from the 3 nearest stations of a listing to the stations near the college; season-pass cost by rail distance from official fare slabs (fixes T21); true monthly cost = rent + compulsory charges + travel; "best value" Pareto frontier over (monthly cost, door-to-door time). Prerequisites: curated station order per line (the OSM `line` tag in V5 is not reliable), official monthly-pass fares entered by an admin, ~20 recorded real trips for validation. Estimate: 2 weeks. |
