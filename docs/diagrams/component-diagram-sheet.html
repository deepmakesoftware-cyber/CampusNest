Brief explanation

CampusNest is a web application in which students find accommodation and roommates near their college, owners list rooms, and administrators verify listings. The Web UI holds no business rules: every request goes through the REST API & Security Layer, which checks the login session, CSRF token and the user's role before calling a service. Seven business services each own one responsibility and offer one interface — for example the Recommendation Engine computes the explainable suitability score using the Listing Service and the Commute & Cost Estimator. Services never talk to the database directly; they read and store data through the Data Access Layer (repositories), and photos go through the Image Store. PostgreSQL, the server's file system and OpenStreetMap are outside the system boundary. All components run inside one Spring Boot application (a modular monolith): a component is a Java package of classes, not a separate microservice.

Note on interface names. IAccount, IListing … are the design contracts. In the code each contract is the set of public methods of the matching Spring service class (e.g. RecommendationService); separate Java interface files were not created because every contract has exactly one implementation.

Trace one action

Success — a student opens “Recommended”:

  1. Web UI sends GET /api/v1/student/recommendations.
  2. The security layer finds a valid session with role STUDENT and calls recommend(studentId) through IRecommendation.
  3. The Recommendation Engine reads the student's preferences (IUserStore), published listings (IListing, IListingStore), commute estimates (ICommute) and review/report counts (IEngagementStore), then scores and ranks the listings.
  4. The ranked list with its score breakdown returns as JSON and the Web UI displays it.

Failure — an owner opens the same address: the security layer answers 403 Forbidden before any service runs, so no student data is read.
